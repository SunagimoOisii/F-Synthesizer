# UX Improvement Roadmap — 初心者・楽しさ視点

> 方針根拠: `PRODUCT_POLICY.md`
> 「理論説明より触って音が変わる体験」「失敗しにくく短時間で気持ちよい結果に到達できる導線」

---

## 設計の核心

**「パラメータを設定する道具」→「音を探索する場所」へのシフト**

現状UIは「設定値を知っていれば使える」構造。
目標は「触ったら何かが変わる → それが気持ちいい」のループを作ること。

---

## Phase 0 — UI アーキテクチャ刷新（案α）

> **採用方針:** `Sound | Music` というオブジェクト種別によるタブ分けを廃止し、
> **「やりたいこと」を起点にしたモード選択** へ移行する。

### 現状の問題

| 問題 | 詳細 |
|---|---|
| タブ名が目的でなくオブジェクト種別 | `Sound` / `Music` は「何を触るか」。初心者には「何をするか」が見えない |
| 音色編集と試聴の往復コストが高い | 音色を変えるたびに `Tone Preview` ボタンを押しに行く必要がある |
| 仮想鍵盤がない | 「シンセなのに弾けない」。遊び場としての体験が始まらない |
| 書き出しが Music タブ内に埋もれる | 初心者には「どこで WAV を保存するのか」が見えにくい |

### 新しい3モード構成

```
[遊ぶ]  [作る]  [書き出す]
```

現行コードの対応: `UIModeTab` の値域を `0/1` から `0/1/2` に拡張し、
各モードのコンテンツを既存の Sound / Music コンテンツから再配置する。

---

### 「遊ぶ」モード（旧 Sound タブ を再構成）

**目的:** 音に出会い、音と遊ぶ。パラメータ設定より先に「音が鳴る体験」を届ける。

```
┌─────────────────────────────────────────────────────────────┐
│  [遊ぶ] [作る] [書き出す]                     Status: ●  │
├───────────────────┬─────────────────────────────────────────┤
│  プリセットブラウザ │  音色エディタ（折りたたみ可サイドパネル）     │
│  [カテゴリ ▼]    │  ┌─────────────────────────────────┐  │
│  ─────────────── │  │  Waveform ▼                     │  │
│  FC_Triangle_Bass │  │  Filter ──────────────────────  │  │
│  FC_Square_Lead   │  │  Envelope ─────────────────────  │  │
│  FM_Bell        ← │  │  LFO / Modulation ─────────────  │  │
│  ─────────────── │  │  Effects ──────────────────────  │  │
│  [Randomize]      │  └─────────────────────────────────┘  │
│  Subtle/Med/Wild  │  波形ビューア + スペクトラムアナライザ      │
├───────────────────┴─────────────────────────────────────────┤
│              仮想キーボード (C2 〜 C6)                       │
│  [■][□][■] ・・・・・・・・・・・・・・・・ [■][□][■]       │
├─────────────────────────────────────────────────────────────┤
│  [Tone Preview]  [Stop]  Chord: [OFF ▼]  VU: ████░░ -3dB  │
└─────────────────────────────────────────────────────────────┘
```

**主な変更点（現行からの差分）:**
- タブ名 `Sound` → `遊ぶ`
- 仮想キーボードを常時表示（最下部固定）
- キーボードのクリックで即 Tone Preview が発火
- プリセットブラウザを左カラムに昇格（現状は `GUIPresetIO` の展開メニュー）
- 音色エディタは右カラムのサイドパネルへ（折りたたみ可）
- VU メーターをアクションバーに配置
- `Play Preview (PR Channel using Selected Slot)` は「遊ぶ」モードでは非表示（複雑さを隠す）

---

### 「作る」モード（旧 Music タブ をそのまま継承）

**目的:** ピアノロールでフレーズを組む。チャンネル管理・ミックスを行う。

現行の Music タブの内容をほぼそのまま移行する。
追加として、チャンネルリストで音色を選択したとき「遊ぶ」モードの音色エディタへ
直接ジャンプするリンクボタン（`[音色を編集]`）を置く。

---

### 「書き出す」モード（新設）

**目的:** Export に集中した専用画面。「どこで WAV を保存するのか」を明確にする。

```
┌────────────────────────────────────────┐
│  出力先: [path/to/output.wav] [Browse] │
│  Format: 44100 Hz / 16bit / Stereo ▼  │
│                                        │
│  書き出し対象: (●) All  ( ) Ch10 のみ  │
│                                        │
│  [Export WAV]    [Play Preview]        │
│                                        │
│  VU: ████████░░░░ -1.2dB  [Stop]      │
│                                        │
│  最近の書き出し:                        │
│  2026-03-27 output.wav (3.2 MB)       │
└────────────────────────────────────────┘
```

現行の `Export WAV` ボタンと出力パス設定を Music タブから移動し、
書き出し専用の軽量ビューに集約する。

---

### 移行コストの見積もり

| 変更 | 影響範囲 | コスト |
|---|---|---|
| `UIModeTab` を 0/1/2 に拡張 | `GUIState`, `MainWindow.inl` | 低 |
| タブバー文言変更 (`Sound→遊ぶ` 等) | `MainWindow.inl` 数行 | 低 |
| 「遊ぶ」コンテンツの再レイアウト | `MainWindow.inl`, `GUIChannelEditor.*` | 中 |
| 「書き出す」モードの新設 | `MainWindow.inl` に新コンテンツブロック追加 | 中 |
| プリセットブラウザの左カラム昇格 | `GUIPresetIO.cpp` の呼び出し位置変更 | 低〜中 |
| VU メーター配置 | `PreviewAudio.cpp` の振幅取得 + 描画追加 | 低 |
| 仮想キーボード | 新規 UI ブロック追加 | 中 |

**着手順の推奨:**
1. タブ名変更 + `UIModeTab` 値域拡張（最小変更で体験の方向感を確認）
2. 「書き出す」モード新設（Export WAV を Music から分離）
3. 「遊ぶ」モードの仮想キーボード + プリセットブラウザ昇格
4. 音色エディタのサイドパネル化

## Phase 1 — 最小投資・最大効果（HIGH）

最初の5分の体験を変える。他の変更に依存せず独立して着手できる。

### 1-A: 仮想キーボード（Sound タブ）

**目的:** 音域全体をクリックだけで即試聴できる。「シンセで遊べる」感を最初の操作で与える。

- Sound タブ下部にクリッカブルなピアノ鍵盤 UI を配置
- クリックで `tonePreviewNoteNumber` を更新し、即座に `Tone Preview` を発火
- 実装的には既存の `previewNoteNumber` の入力手段を鍵盤に拡張するだけ

**受け入れ条件:**
- [ ] 全音域（少なくとも C2〜C6）をクリックで試聴できる
- [ ] DrumKit モード時は非表示（既存 `tonePreviewNoteNumber` の非表示ロジックと統一）

---

### 1-B: Randomize ボタン（Sound タブ）

**目的:** 「壊れても戻せる」安心感が探索を促進する。Happy accident による発見体験。

- `[Randomize]` を Tone Preview ボタン近傍に配置
- 強度プリセット: Subtle / Medium / Wild（変化量のスケール係数）
- 音源タイプ（Waveform/FM/Analog/Noise/Drum）は変えない。パラメータのみランダム変化
- 実行前に内部で A バッファ（後述 2-C）へ自動スナップショット

**受け入れ条件:**
- [ ] Subtle で音色の雰囲気が保たれる（極端なクリップやサイレントにならない）
- [ ] Wild で毎回明確に異なる音が出る
- [ ] 実行後 Undo（または A バッファ復元）で元に戻せる

---

### 1-C: パラメータホバー文言の音楽的言語化

**目的:** 専門用語より「何が起きるか」を伝える（`PRODUCT_POLICY.md` 判断ルール 3）。

対象パラメータの `gui-help` の `impact` を以下の方針で書き直す:

| パラメータ | 現状イメージ | 改善後イメージ |
|---|---|---|
| `filterCutoffHz` | `フィルターカットオフ周波数` | `音の明るさ。上げると輝き、下げると暗く遠ざかる` |
| `pulseWidth` | `パルス幅 0.05〜0.95` | `音の細さ・鋭さ。LFOで揺らすとクラリネット的な揺らぎに` |
| `hardSyncEnabled` | `ハードシンク有効` | `倍音の金属感を追加。クラシックなジッパーサウンドに` |
| `ringModEnabled` | `リングモジュレーション` | `2つの音が干渉して生まれる金属的・ベル的な響き` |
| `lfo1.delayMs` | `LFO ディレイ (ms)` | `音が鳴り始めてからビブラートがかかるまでの間 (ms)` |
| `modEnv.curve` | `モジュレーションエンベロープカーブ` | `変化の加速感。低いと急激に、高いとなだらかに変化` |

**受け入れ条件:**
- [ ] 主要導線（音源タイプ選択 / Filter / Envelope / LFO / Modulation）でホバー文言欠落なし
- [ ] `gui-help-hover-acceptance-checklist.md` に反映済み

---

### 1-D: VU メーター（プレビュー再生中）

**目的:** 「ちゃんと音が出ているか」の即時確認。クリップ警告で音量ミスを気づかせる。実装コストが低く即効性が高い。

- Tone Preview / Play Preview 中にリアルタイムのレベルメーターを表示
- ピーク超過時に赤ピークホールドを表示（クリップ警告）
- 既存の PCM バッファから最大振幅を取得するだけで実装可能

**受け入れ条件:**
- [ ] 再生中にレベルが動的に変化する
- [ ] クリップ（|sample| > 1.0）時に赤表示になる
- [ ] 停止後もピーク値を数秒保持する

---

### 1-E: 音源タイプ別スタート音色テンプレート

**目的:** 「Init（全パラメータ初期値）」1種類から、用途別の出発点を複数提供する。ゼロからの設定コストをなくす。

- Waveform: `Warm Pad / Bright Lead / Sub Bass`
- FM: `Bell / Electric Piano / 8bit Blip`
- Analog: `Acid Bass / Soft Brass`
- Noise: `Wind / Static`
- Drum: `808 Kick / Snare Hit`
- 実装は JSON プリセットファイルの追加のみ（コード変更なし）

**受け入れ条件:**
- [ ] 各音源タイプで最低 2 種類の初期テンプレートが選べる
- [ ] テンプレート選択後、即座に `Tone Preview` で確認できる

---

### 1-F: クラシックサウンドのレシピプリセット

**目的:** MVP の「FM音源などレトロゲームにあるサウンドに初心者でも簡単に触れられる」に直結。音色の作り方を体で覚える。

- レトロゲームを再現したプリセット集を同梱:
  - `FC_Triangle_Bass`（ファミコン三角波ベース）
  - `FC_Square_Lead`（ファミコン矩形波メロディ）
  - `GB_Noise_Drum`（ゲームボーイノイズ打楽器）
  - `FM_Bell`（DX7 的ベル）
  - `FM_Slap_Bass`（FM スラップベース）
- プリセット JSON の `description` フィールドに「このパラメータがレトロ感の肝」のコメントを付与
- 実装は JSON ファイルの追加のみ（コード変更なし）

**受け入れ条件:**
- [ ] 5 種類以上のレトロゲームサウンドプリセットが同梱される
- [ ] 各プリセットに `description` で音の特徴説明が付いている

---

### 1-G: Undo/Redo（Sound エディタ）

**目的:** 「戻れない恐怖」が探索を止める最大の原因。失敗しても安全な探索を保証する（`PRODUCT_POLICY.md`「失敗しにくい」）。

- Sound タブのパラメータ変更を履歴スタックに積む
- Ctrl+Z / Ctrl+Y で操作を元に戻す/やり直す
- ピアノロールの Undo/Redo とは独立したスタック
- セッション中のみ保持（ファイル保存は不要）

**受け入れ条件:**
- [ ] パラメータを変更後 Ctrl+Z で直前の値に戻る
- [ ] Ctrl+Y でやり直しができる
- [ ] 音源タイプ切替は Undo 対象外（設計の複雑化を避ける）

---

## Phase 2 — 体験の深みを増す（MEDIUM）

Phase 1 完了後に着手。各タスクは独立して実施可能。

### 2-A: ADSR / LFO グラフィカル表示（編集可能カーブ）

**目的:** 「数値ではなく形で覚える」体験。エンベロープの概念を視覚で伝える。

- Envelope セクションの隣にカーブ描画エリアを追加
- ADSR の形状をリアルタイムで線グラフ表示（`ImGui::PlotLines` 拡張）
- 将来的には点のドラッグでパラメータ変更（Phase 3 候補）
- LFO も同様に波形プレビュー（Square/Saw/SampleAndHold を含む全波形）を常時表示

**受け入れ条件:**
- [ ] A/D/S/R の数値変更時にカーブがリアルタイム更新される
- [ ] LFO 波形プレビューが全 `LfoWave` 列挙値に対応している

---

### 2-B: FM アルゴリズムのオペレーター接続図

**目的:** Algorithm 0〜7 が「接続図」として見えると、FMの理解が劇的に改善する。

- コンボボックス選択時、隣にオペレーター接続のブロック図を描画
- DX7 スタイル: Op矩形 + 矢印（キャリア/モジュレーター関係を図示）
- ImGui の `DrawList` で描画（外部ライブラリ追加なし）

**受け入れ条件:**
- [ ] Algorithm 0〜7 全ての接続図が表示される
- [ ] コンボ変更時に即座に図が切り替わる

---

### 2-C: A/B バッファ比較

**目的:** 「変化を聴き比べる」行為が音作りの学習効果を高める。

- `[Save A]` ボタンで現在の音色パラメータをメモリに保存
- `[Restore A]` で復元（Randomize の Undo としても機能）
- `[A→B Play]` で A→B を交互に Tone Preview（将来実装）

**受け入れ条件:**
- [ ] Save A → パラメータ変更 → Restore A で完全に元に戻る
- [ ] セッション中のみ保持（ファイル保存は不要）

---

### 2-D: プリセットのカテゴリ分類 + フィルタ

**目的:** 「Pad系の音から探したい」導線。初心者が出発点を見つけやすくする。

- プリセット JSON にオプションフィールド `"category"` を追加（`Bass/Lead/Pad/Keys/FX/Drum`）
- `GUIPresetIO.cpp` のプリセット一覧にカテゴリフィルタを追加
- 既存プリセットは `category` 未指定で動作（後方互換）

**受け入れ条件:**
- [ ] カテゴリ未指定のプリセットが従来通り読み込める
- [ ] カテゴリ指定時にフィルタリングが機能する

---

### 2-E: ドラムチャンネルのステップシーケンサービュー（Music タブ）

**目的:** ピアノロールより直感的なリズム入力 UI。`GUI_REQUIREMENTS.md` の「ドラム向け短縮導線」要件と一致。

- Music タブで ch10（ドラム）選択時に切替ボタンを表示（`Piano Roll` / `Step Seq`）
- 16ステップ × 主要パーカッション行（Kick/Snare/HH等）のグリッド
- グリッド ON/OFF がノートの追加/削除に対応

```
Kick  [■][ ][■][ ] [■][ ][■][ ]
Snare [ ][ ][■][ ] [ ][ ][■][ ]
HH    [■][■][■][■] [■][■][■][■]
```

**受け入れ条件:**
- [ ] ステップ編集結果が `Play Preview` / `Export WAV` に反映される（ピアノロールデータと同じ書き出しパスを使用）
- [ ] ch10 以外では表示されない

---

### 2-F: プリセット間モーフィング（Morph Slider）

**目的:** 2つのプリセットを選んでスライダーを動かすと、パラメータが補間されながら音が変わる。「AとBの中間の音が欲しい」という直感操作で新しい音に出会える。探索系機能の中で最も発見性が高い。

- `[Preset A]` と `[Preset B]` を選択し、`Morph` スライダー（0.0〜1.0）で補間
- 数値パラメータは線形補間。bool / 列挙値は閾値（0.5）で切り替え
- スライダー操作のたびに Tone Preview を自動再生（または手動トリガー）

**受け入れ条件:**
- [ ] スライダー 0.0 で Preset A、1.0 で Preset B の音になる
- [ ] 中間値でクリップやサイレントにならない（パラメータ範囲内に収まる）

---

### 2-G: コードモード（仮想キーボード拡張）

**目的:** 1キーで和音を鳴らせる。理論を知らなくてもそれっぽいフレーズが出る。1-A（仮想キーボード）完了後に着手。

- キーボード上部に `Chord` トグルを配置
- コード種別: Major / Minor / 7th / Minor 7th / Sus4
- 選択したルートキー + コード構成音を同時に `Tone Preview` で発音

**受け入れ条件:**
- [ ] Chord OFF 時は従来の単音試聴と同じ動作
- [ ] Chord ON 時に指定コードの構成音が全て鳴る

---

### 2-H: タップテンポ

**目的:** 手拍子でBPMを合わせる直感操作。Delay の `tempoSync` やアルペジオのレートと連動させると即効性が高い。

- `[Tap]` ボタンを連打すると直近 4 打の間隔の平均から BPM を算出
- 算出した BPM を `masterTempo` に反映
- Music タブのテンポ表示エリアに配置

**受け入れ条件:**
- [ ] 4 回以上タップで安定した BPM が算出される
- [ ] 算出 BPM が Delay tempoSync とアルペジオレートに即座に反映される

---

### 2-I: エフェクトチェーン視覚化

**目的:** SampleRateReducer → BitCrusher → Chorus → Flanger → Delay → Reverb の順序と ON/OFF を一目で把握できる。

- 横並びのブロックチェーン図で各エフェクトを表示
- 各ブロックをクリックして ON/OFF トグル
- OFF のブロックはグレーアウト、ON のブロックはハイライト
- ImGui の `DrawList` で描画（外部ライブラリ追加なし）

**受け入れ条件:**
- [ ] 全 6 エフェクトのブロックが表示される
- [ ] ブロッククリックで有効/無効が切り替わり、音に即座に反映される

---

### 2-J: ピアノロールのリフテンプレート

**目的:** 空プロジェクトでの「何から始めればいいか」問題を解消する。Music タブ初回の壁を下げる。

- `[Load Template]` から選択できる 2〜4 小節のスターターパターンを同梱:
  - `8bit Melody`（シンプルな単音メロディ）
  - `4 on the floor`（4 つ打ちキック）
  - `Simple Bass Line`（ルート音を中心にした単音ベース）
- テンプレートは MIDI or ピアノロール JSON として保存
- 既存ノートへの追加か上書きかを選択できる

**受け入れ条件:**
- [ ] テンプレート読み込み後 `Play Preview` でそのまま鳴らせる
- [ ] 既存ノートへの上書き前に確認ダイアログを表示する

---

## Phase 3 — 将来の差別化要素（LOW）

Phase 2 完了後の候補。設計コストが高いため十分な検討後に着手。

### 3-A: モジュレーションルーティング図

LFO1 / Env2 / ModWheel → Filter Cutoff / Pitch / PulseWidth 等の接続を、線で結ばれたフロー図で表示。
現状 0〜7 のルートをテキストリストで管理しているが、全体像が見えにくい。
実装コストが高い（DrawList で動的レイアウト）ため Phase 3 に据え置く。

### 3-B: ビジュアルテーマ（レトロゲーム風スキン）

ImGui のスタイル設定だけで実装できる。ゲームボーイのグリーンモノクロ / ファミコン黒赤 / CRT スキャンライン風など。
「遊び心重視」のブランドトーンと直結し、ツールではなく楽器として扱われる体験を作る。
機能的な改善ではないため最後の候補とする。

### 3-C: マクロスライダー（1つで複数パラメータを連動制御）

> **→ `docs/codex-prompts-3layer-ux.md` の Layer 2 として実装中。本項は実装ドキュメントのポインタのみ残す。**

固定マクロ（明るさ / 荒さ / 揺れ / 鳴り方）で複数パラメータを連動制御する。
ソースタイプ別マッピング・双方向同期ポリシー・各タスクのプロンプトは `codex-prompts-3layer-ux.md` を参照。

### 3-D: スケールスナップ（ピアノロール）

ノート配置を指定スケール（C major / A minor / Blues 等）に自動スナップ。
「音痴にならない」保証で初心者のメロディ作成の壁を下げる。

### 3-E: ADSR カーブの直接ドラッグ編集

2-A のカーブ表示を拡張し、グラフ上の点をドラッグしてパラメータを変更。
