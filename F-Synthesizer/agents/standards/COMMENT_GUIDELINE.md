# COMMENT_GUIDELINE

このファイルは日常作業で常時参照する必須版です。
詳細規定は `COMMENT_GUIDELINE_FULL.md` を参照してください。

## 1. 目的

- 誤用リスクの高い箇所だけを短く明確に説明する。
- コメントの過剰追加を避け、可読性と保守性を保つ。

## 2. 必須ルール

- 全関数への一律コメントは禁止。
- コメント対象は次に限定する。
  - 誤用リスクの高い API 境界
  - 並行性、所有権、スレッド前提
  - 境界値処理、例外的分岐
  - 性能最適化の前提やトレードオフ
- 1 ファイルあたりのコメント追加は原則 20 行以内。
- `TODO` / `FIXME` をコードへ残さない。
- 抽象語のみの説明を禁止し、根拠や条件を明示する。
- 「契約」「誤用」「最適化」など抽象語を使う場合は、直後に具体条件（何が起きるか/何を防ぐか）を併記する。
- 一般的でない言い回し（例: 「計算系」「非null」）は避け、通常の技術用語（例: 「計算」「null でない」）に置き換える。
- 口語的・省略的な語（例: 「後勝ち」「exe 位置」「〜経路」）は避け、意味が一読で通る表現に置き換える。
- 英語の一般名詞を単独で使わず、必要ならコード識別子と併記する（例: 「future」ではなく「runFuture」）。
- 外来語は日本語で同義に置き換えられるなら置換する（例: 「フォールバック」→「代替値」）。

## 3. 関数コメントの最小契約

公開関数または高リスク関数では、必要に応じて次を記述する。

- 前提条件（入力範囲、呼び出し順序）
- 副作用（状態変更、I/O、キャッシュ更新）
- 失敗時の扱い（戻り値、例外、無視条件）

## 4. 詳細版の参照条件

次のいずれかに当てはまる場合のみ `COMMENT_GUIDELINE_FULL.md` を読む。

- クラス/構造体コメントの粒度判断で迷う
- 呼び出し経路・責務境界の記述テンプレが必要
- レビュー運用や例外規定の適用判断が必要
