# GUI スリム化・スマート化メモ

作成日: 2026-03-29  
目的: 現状GUIにおける「必要ない部分」「無駄な部分」「もっとスマートにできる部分」を整理する。

## 必要ない部分（削減候補）

- `Save Project` と `Save All` の同時常設
  - 初心者視点では違いが分かりづらく、選択コストが高い
- `Copy MIDI` の常設ボタン
  - 利用頻度が低く、常設UIを圧迫しやすい
- `Logs` の常時強い存在感
  - 通常操作時はノイズになりやすい

## 無駄な部分（重複候補）

- `作る` 内の情報密度過多
  - Layer2（探索）と Layer3（詳細）の境界が視覚的に近く、目的切替がしづらい
- `Recover:*` 系導線の常時露出
  - 例外導線が主導線と同じ強さで見える
- 補助説明の重複
  - `TextDisabled` と hover help が同趣旨を重複している箇所がある

## もっとスマートにできる部分

- ヘッダ再整理
  - 常設優先: `Status / Theme / Slot`
  - 退避候補: `Scale`（設定メニューへ）
- モード別の主アクション1本化
  - `作る`: `Preview`
  - `遊ぶ`: `Play`
  - `書き出す`: `Export`
- Source別の自動折りたたみ
  - 非該当パラメータ群を初期折りたたみにして視認負荷を軽減
- 視線導線の固定
  - 「触って変化が分かる要素（ADSR/LFO等）」を上
  - 「数値微調整」を下に統一

## 優先度（短時間で効く順）

1. `Logs` 既定折りたたみ + 表示強度抑制  
2. アクションバーの主ボタン集約（モード別）  
3. `Copy MIDI` 退避（詳細メニュー化）  
4. `Save` 導線の再編（常設1本 + 詳細保存）  
5. Source別の自動折りたたみ導入  

## 期待効果

- 初見ユーザーの迷い削減
- 操作判断の高速化（選択肢過多の抑制）
- 「触って音が変わる」体験への集中
