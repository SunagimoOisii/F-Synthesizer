## v7基本方針（ドラフト）

- 作成日: 2026-02-22
- 位置づけ: 方向性の確定前メモ（このチャットでの参照用）

### 1. 目的

- `Sound` と `Music` の責務を明確に分離し、UIの迷いを減らす。
- 音色変更が楽曲結果に与える影響を可視化し、再現性を高める。
- 将来拡張（トラック/レイヤー等）に耐えるデータモデルに寄せる。
- 最優先は `音の気持ちよさ` と `即時フィードバック` を崩さないこと。

### 1.1 v7プロダクトデザイン反映ルール（優先）

- 本メモの v7方針は、`GUI_REQUIREMENTS.md` の旧記述と差分がある場合に優先する。
- 反映時は「初心者が迷わない」「編集から試聴まで最短導線」を第一条件とする。
- `link/snapshot` など複雑化し得る機能は段階的開示（通常UIでは最小表示）とする。

### 2. 現状方針の問題点（確認済み）

- 役割境界が曖昧  
  `Sound` の音作りと `Music` の演奏調整が同じ `channel` 概念で混ざりやすい。
- 依存関係が暗黙的  
  `Music` がどの音色を参照しているかが分かりにくい。
- 再現性が弱い  
  後から音色が変わると同じプロジェクトでも書き出し結果が変わり得る。
- 拡張性が不足しやすい  
  チャンネル固定モデルだけだと将来の機能追加が窮屈。
- プレビュー責務が衝突  
  「音色確認」と「楽曲確認」がUI上で近く、意図がぶれやすい。
- 保存単位が直感に合いにくい  
  何が保存されるかが分かりにくく、運用ミスにつながる。

### 3. v7基本方針（解消方針）

1. 責務分離
- `SoundAsset`（音色定義）と `MusicProject`（MIDI/演奏調整/出力設定）を分離する。
- `Sound` タブは `SoundAsset` 編集専用、`Music` タブは `MusicProject` 編集専用にする。

2. 依存明示
- `MusicProject` に `channelAssignments[0..15] = soundAssetId` を持たせる。
- UIで「現在参照している音色」を常時確認できるようにする。

3. 再現保証
- 参照モードを `link` / `snapshot` の2種で定義する。
- 既定は `snapshot` 優先として、書き出し結果の再現性を担保する。
- 初心者向けの通常導線では `snapshot` を推奨表示し、`link` は詳細設定に配置する。

4. 拡張余地
- 内部モデルは `Part { midiChannel, soundAssetId, mix }` を前提にし、将来拡張に備える。
- UIは当面16chを維持して段階移行する。

5. 操作明確化
- Preview操作名を責務別に固定する。
- `Sound`: `Tone Preview`, `Channel Preview`
- `Music`: `Song Preview`, `Range Preview`, `Export WAV`

6. 保存一貫
- 保存対象を3層に整理する。  
  `SoundAsset` / `MusicProject` / `Workspace(UI state)`
- Save時に対象を明示し、必要に応じて `Save All` を提供する。
- 主導線は `Save Project` を基本にし、`Save All` は補助導線にする。

### 4. タブ責務（ドラフト）

- `Sound`
  - 音色設計（波形/FM/Drum、ADSR、音色単位パラメータ）
  - 音色試聴（単音/選択対象）
  - 音色プリセット保存・複製・読み込み
- `Music`
  - MIDI読み込み、ピアノロール編集
  - チャンネル演奏調整（Mute/Solo/Level/Pan/Gain）
  - 音色割当（MIDI ch -> SoundAsset）
  - 曲プレビュー、範囲プレビュー、WAV書き出し

## v7操作感仕様（ドラフト）

- 作成日: 2026-02-22
- 位置づけ: Phase/Tasks分解前の操作契約メモ

### A. 初回体験

- 起動直後でも「とりあえず音を出す」「とりあえず書き出す」が可能であることを優先する。
- 深い機能理解がなくても主要操作へ到達できる導線を維持する。

### B. プレビュー操作契約

- プレビュー実行時は毎回再生成する（キャッシュ再生はしない）。
- `Sound` / `Music` でプレビュー挙動は分けない。
- 編集中にプレビュー中であっても再生は継続する。
- ループ対象は「全体」「範囲」の両方を許可する。
- 範囲プレビューが有効な場合は、常に範囲優先で再生する。
- タブ切替時は再生を停止する。
- 再生中に `Export` した場合は、再生を停止して書き出し処理を開始する。
- `Stop` は再生とレンダの両方を停止対象とする。
- 反応速度目標（押下から発音まで）は v7 では規定しない（課題化のみ）。
- MIDI不正などの再生エラーはダイアログで通知する。

### C. Music編集粒度

- v7は MIDI 16ch 固定で扱う。
- 音色割当は当面 `chごとに1音色` 固定で扱う（将来拡張は別途検討）。
- ミックス項目は `Mute/Solo/Level/Pan/Gain` を全表示する。
- `PR Channel` は表示/編集専用とし、書き出し対象の決定には連動させない。
- 書き出し対象は別UIで明示選択する（`All Channels` / `Single Channel`）。
- 1チャンネル書き出し、全ch書き出しの両方をサポートする。
- 音量/パン等の時間自動化は v7 非対応とする。
- ドラムch（ch10想定）は特別扱いを行う。
- 編集結果は即時反映とする（適用ボタン方式は採用しない）。

### D. 保存・遷移・エラーUX

- 未保存状態で終了またはプロジェクト切替を行う場合は警告を表示する。
- エラー時UXは推奨構成を採用する（ログ + 画面内表示 + 修正アクション）。
