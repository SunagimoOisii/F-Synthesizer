## 前提: プロダクトデザイン判断軸

`docs/PRODUCT_POLICY.md` より抜粋。機能判定はこの3軸で評価する。

- **触変**: 「触って音が変わる体験」への貢献度
- **安全**: 「失敗しにくく短時間で気持ちよい結果に到達できる」への貢献度
- **レトロ**: MVP体験「レトロゲームサウンドに触れる」への直結度

非目標: 高度DAW機能 / プロ向け深いパラメータ / プラグイン / 共同編集

### A. フロー改善（UX起点）

#### A-1. Auto Preview（パラメータ変更→自動再試聴）
- **触変: ★★★ / 安全: ★★★ / レトロ: −**
- 概要: パラメータ編集後 400ms 無操作で `StartGUISoundTonePreview` を自動起動する
- 実装箇所: `GUIState` にdebounceタイマー追加 → RunLoop or MainWindow.inl で判定
- 実装コスト: **低**（既存レンダ基盤はそのまま）
- メモ:
  - 「ボタンを押す」という断絶が消える = 体験の根本改善
  - Opt-in（チェックボックス）にして、重い曲は手動に切り替えられるとよい
  - 対象は "Play Tone" 相当（単音）のみ。曲全体の自動再生は不要
  - "Play Tone" ボタンは削除して、チェックボックスでの自動再生on, off のみにする

### B. 音響エフェクト（Shaper後段）

#### B-1. ビットクラッシャー
- **触変: ★★ / 安全: ★★★ / レトロ: ★★★**
- 概要: 出力を N bit に量子化。4bit=ゲームボーイ系、8bit=ファミコン系
- パラメータ: `bits`（1〜16, default=16=off）
- 実装箇所: Shaper Layer 後段（drive の後）または独立した `RetroFX` 層
- 実装コスト: **低**（量子化ステップ計算のみ）
- メモ: `bits=16` でバイパス、`bits<=8` で目立ったレトロ感。初心者に説明しやすい

#### B-2. サンプルレートリデューサー
- **触変: ★★ / 安全: ★★ / レトロ: ★★★**
- 概要: N サンプルごとに値を保持（ダウンサンプリング擬似再現）。エイリアシング感が出る
- パラメータ: `sampleRateRatio`（0.0〜1.0, 1.0=off）または直接Hz指定
- 実装箇所: ビットクラッシャーと同層
- 実装コスト: **低〜中**
- メモ: ビットクラッシャーと組み合わせると8bit感が強まる。2つセットで実装推奨

#### B-3. コーラス / フランジャー
- **触変: ★★ / 安全: ★★ / レトロ: ★**
- 概要: 短いディレイラインをLFOで変調。厚みと揺らぎ
- 実装コスト: 中
- メモ: レトロ感への寄与は低い。Wavetableやアナログ模倣路線で活きる

### C. FM体験改善

#### C-1. FM アルゴリズムテンプレートプリセット
- **触変: ★ / 安全: ★★★ / レトロ: ★★★**
- 概要: アルゴリズム×用途の起点プリセットを整備
  - algo 0 (2op直列): bass / lead 3〜5バリエーション
  - algo 1 (2ペア並列): pad / chord
  - algo 2 (1変調→3キャリア): organ / bell
  - algo 3 (チェーン): ディープベース / FMならではの特殊音
- 実装コスト: **低**（JSONファイル追加のみ）
- メモ: FMの「パラメータ感度が高く操作難度が上がりやすい」問題への対策
  - fm.md D項「安全域プリセットと初期値整備」にも記録済み

#### C-2. 「テンプレートに戻す」ボタン（GUIレベル）
- **触変: − / 安全: ★★★ / レトロ: ★★**
- 概要: 現在アルゴリズムの推奨初期値に一発リセットするボタン
- 実装コスト: **低**（アルゴリズム別デフォルト値テーブルをGUIに追加）
- メモ: 初心者の「壊れた音から戻れない」状態を解消するリカバリー導線

### D. 探索支援

#### D-1. プリセット充実（カテゴリ整理）
- **触変: ★★ / 安全: ★★★ / レトロ: ★★**
- 概要: 既存プリセットのカテゴリ整理 + 各方式の代表音色追加
- 実装コスト: **低**
- 優先カテゴリ: FM-ブラス / FM-ベース / FM-ベル / PSG-lead / PSG-bass / Drum系
- メモ: 「狙ったレトロ感が出せた」成功指標への直結

### F. MIDI表現力拡張

#### F-1. Modwheel (CC1) → LFO depth 連動
- **触変: ★★ / 安全: ★★ / レトロ: ★**
- 概要: CC1受信をModMatrixのLFO depth変調にルーティング
- 実装コスト: 低（CC1値をchannelModwheelとして保持 → Renderer内でlfo.depthに掛ける）
- メモ: Tier1でCC1は`RenderState`に入ったはず。あとはRenderer側でModulationConfigへの適用のみ

#### F-2. PitchBend レンジ可変（RPN0）
- **触変: − / 安全: − / レトロ: ★**
- 概要: MIDIのRPN0でPitchBendレンジを±2〜±12半音で変更可能に
- 実装コスト: 低
- メモ: 現状±2半音固定。一部レトロゲームMIDIに必要なケースがある

### E. 新規合成方式（優先度低）

#### E-1. Wavetable合成
- **触変: ★★ / 安全: ★ / レトロ: ★★**
- 概要: 位相に応じてサンプル列を参照する発振器 + 波形モーフィング
- 実装コスト: 高（新Source type追加、UIが複雑化しやすい）
- メモ: UIの複雑化で「失敗しにくく」に反しやすい。method-boundaries.md更新要

#### E-2. 加算合成（Additive）
- **触変: ★ / 安全: ★ / レトロ: ★**
- 概要: 倍音ごとの振幅・位相・包絡を独立管理
- 実装コスト: 高
- メモ: 初心者には難易度高すぎ。非目標寄り

#### E-3. PCMサンプル再生
- **触変: ★ / 安全: ★ / レトロ: ★★**
- 概要: ループ・ピッチ追従・補間を含むサンプル再生
- 実装コスト: 高（サンプル管理・フォーマット対応）
- メモ: 内蔵サンプル限定（ユーザー読み込みなし）にすれば管理コスト抑制可

### F. MIDI表現力拡張

#### F-3. Channel Pressure（Aftertouch）対応
- **触変: ★★ / 安全: ★★ / レトロ: ★**
- 概要: `0xD0` をパースし、チャンネル単位の表現量として ModMatrix に入力
- 実装コスト: 中（Parser/Sequencer/Event処理/Modulation source 追加）
- メモ: Poly Aftertouch より先に対応すると実装量を抑えやすい

#### F-4. Polyphonic Key Pressure（Poly Aftertouch）対応
- **触変: ★★★ / 安全: ★★ / レトロ: ★**
- 概要: `0xA0` をノート単位の圧力値として保持し、voiceごとに反映
- 実装コスト: 中〜高（noteInstanceID 単位の状態管理が必要）
- メモ: Voice lifecycle（NoteOn/Off）との整合を優先設計

#### F-5. NRPN 一般対応（RPN0以外含む）
- **触変: ★★★ / 安全: ★★ / レトロ: ★**
- 概要: `CC99/98 + CC6/38` の組み合わせを汎用デコードし、目的地にマップ
- 実装コスト: 中
- メモ: まずは「受信・保持のみ」→ 次段で音源パラメータ適用の2段階実装

#### F-6. SysEx（0xF0/0xF7）受信ポリシー整備
- **触変: ★ / 安全: ★★★ / レトロ: ★★**
- 概要: 破棄のみから、ログ可視化/ベンダ別許可などの扱い方針を定義
- 実装コスト: 低〜中
- メモ: 当面は音源制御に使わず「安全に無視 + 診断可能化」を優先

#### F-7. Meta Event 拡張（Tempo以外）
- **触変: ★ / 安全: ★★★ / レトロ: ★**
- 概要: `0x51`/`0x2F` 以外の主要Meta（Time Signature等）を最低限パース
- 実装コスト: 低〜中
- メモ: まずは再生挙動に使わず統計/ログ出力に反映

#### F-8. SMPTE division MIDI 対応
- **触変: ★★ / 安全: ★★★ / レトロ: ★**
- 概要: ヘッダ division の SMPTE 形式を tick->time 変換できるようにする
- 実装コスト: 中
- メモ: 現状は PPQ のみ対応。Parser 側の早期リターンを解消する

#### F-9. MIDI Format 2 対応
- **触変: ★★ / 安全: ★★★ / レトロ: ★**
- 概要: format 2（独立パターン群）を受理し、再生方針を定義
- 実装コスト: 中
- メモ: 互換性重視なら「単一パターン選択」から段階導入
