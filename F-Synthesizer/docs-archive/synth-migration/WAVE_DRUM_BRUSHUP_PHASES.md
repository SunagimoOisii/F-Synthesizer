# WAVE_DRUM_BRUSHUP_PHASES

最終更新: 2026-02-23  
対象: `waveform` / `drum` / `drumkit`  
目的: 音の説得力を先に上げる

## 0. 方針

- 先に `waveform + drum` の完成度を上げる。
- 他方式（noise/fm/未実装方式）は「壊さない・境界を守る」を優先する。
- 各フェーズで AB 比較（同一MIDIの ON/OFF）を必須にする。

## 1. 優先軸（プロダクトデザイン込み）

1. 音の説得力（最優先）
2. 音作りフロー分離（Soundで作る、Musicで適用）
3. 再現性（同一条件で同一結果）
4. 安全性（clip/NaN/極端値対策）
5. 保守性（境界の明文化、重複実装の抑制）

## 2. フェーズ構成

## Phase A: 品質基準固定（Waveform/Drum）

目的:
- 「良い音」の判断基準を先に固定し、実装の迷走を防ぐ。

実施:
- `waveform`（bass/lead）と `drum`（kick/snare/hat）の評価項目を定義。
- ピーク上限、clip許容、AB判定基準を固定。
- テストMIDIの用途を分離（音色検証用 / ミックス検証用）。

完了条件:
- 基準がドキュメント化され、次フェーズの受け入れに使える。

Phase A 決定仕様:
- 評価観点（waveform）:
  - ベース: 低域の芯、音程感、過大なうねりの有無
  - リード: 抜け、痛さ（耳障り帯域）、発音の明瞭さ
- 評価観点（drum）:
  - kick: 低域の土台とアタックの両立
  - snare: 胴鳴りとノイズ帯域のバランス
  - hat: 抜けと耳障りのバランス
- 数値基準（初期）:
  - clip: `0`（必須）
  - peak: `<= 0.90`（統合チューニング前の単体検証）
  - AB差分: `diff_rms > 0.003` を「変化あり」の最低ラインとする
- AB判定ルール:
  - 必須: 数値比較（peak/rms/clip/diff）
  - 必須: 聴感メモ（良化/悪化/判断保留 + 10秒以内の差分時刻）
  - 採用条件: clip 0 を維持しつつ、狙い（太さ/抜け/バランス）に一致
- テストMIDI役割分離:
  - 音色検証用（waveform中心）:
    - `assets/midi/smoothing_phaseF_ab.mid`
  - ミックス検証用（既存楽曲寄り）:
    - `assets/midi/test.mid`
    - `assets/midi/test2.mid`

## Phase B: Waveformブラッシュアップ

目的:
- ベース/リードで「ピコピコ感」を脱し、楽曲に載る質感へ引き上げる。

実施:
- 推奨レンジを固定（filter/modulation/smoothing）。
- ベース用プリセット2種、リード用プリセット2種を作成。
- 破綻しやすい設定（過大detune/過大sub）を安全域へ寄せる。

完了条件:
- 4プリセットで用途別の差が明確。
- ABで改善が確認でき、clip 0 を維持。

## Phase C: Drumブラッシュアップ

目的:
- ドラムが過大になり過ぎず、抜けとアタックを維持したまま使える状態にする。

実施:
- kick/snare/hat の基準プリセットを作成。
- 音量・帯域の基準値を固定（ドラム暴れを防止）。
- one-shot前提を守り、アタック劣化を招く処理は避ける。

完了条件:
- 3プリセットで基準リズムが成立。
- Waveform同居時にも過大ピークを起こさない。

## Phase D: Waveform + Drum 統合チューニング

目的:
- 単体音色ではなく、同時再生時の実用品質を確保する。

実施:
- 低域（kick/bass）と中高域（snare/lead）の帯域衝突を整理。
- チャンネルミックス基準（level/pan/gain）を固定。
- 書き出し時のヘッドルーム基準を確立。

完了条件:
- 統合MIDIで一貫してバランスが取れる。
- AB再実行で再現性がある。

## Phase E: 運用固定（テストとドキュメント）

目的:
- 1人開発で回し続けられる検証運用へ固定する。

実施:
- ABテスト手順を `config/samples` とコマンド単位で固定。
- 結果記録テンプレート（peak/rms/clip/diff + 聴感メモ）を固定。
- `waveform.md` / `drum-drumkit.md` / `STATUS.md` を更新。

完了条件:
- 新規改善が同じ手順で検証できる。
- 方式境界ドキュメントと整合している。
