# Development Notes

## 作業分類

### 1. `refactor`
- 対象: リファクタリング、コメント追加・整理、可読性改善
- 目的: 振る舞いを変えずに保守性を高める

### 2. `feat-core`
- 対象: 音源コア、合成ロジック

### 3. `feat-audio`
- 対象: DSP、エフェクト、ミキシング

### 4. `feat-control`
- 対象: MIDI、オートメーション、パラメータ制御

### 5. `feat-data`
- 対象: プリセット、保存形式、入出力

### 6. `feat-perf`
- 対象: 低遅延化、CPU/メモリ最適化

### 7. `feat-infra`
- 対象: テスト、CI、ビルド、開発基盤

### 8. `gui-cleanup`
- 対象: GUI整理、UI一貫性改善

### 9. `gui-feature`
- 対象: GUI新機能追加

## 現状課題・改善ポイント（優先度順）

### P1. MIDI回帰テストの実行安定化（`feat-infra`）
- 課題:
  - `scripts/midi_regression.ps1` が実行ディレクトリ依存で失敗するケースがある。
  - `check.ps1` から自動実行されないため、回帰を継続検知しづらい。
- 改善ポイント:
  - `--config` の参照を絶対パスまたは実行前 `Push-Location` で固定する。
  - `check.ps1` に `midi_regression.ps1` の実行オプションを統合する。

### P2. 同一ノート重なり時の `NoteOff` 対象精度（`feat-core`）
- 課題:
  - 同一 note 重なりで、意図した voice と異なる `NoteOff` が起こる可能性がある。
- 改善ポイント:
  - 現在の「先頭一致を閉じる」方針を見直し、直近一致など明示ルールへ変更する。
  - 判定ルールをコメントとテストケースで固定化する。

### P3. WAV出力のビット深度整合（`feat-data`）
- 課題:
  - 実データが 16bit 固定処理で、ヘッダ値との不整合リスクがある。
- 改善ポイント:
  - 16bit固定を明示して強制するか、可変bit深度の実データ書き出しに対応する。
  - 設定読込・GUI・Writer の制約を一貫させる。

### P4. ドキュメント同期の運用強化（`refactor` / `feat-infra`）
- 課題:
  - `STATUS.md` の Priority/Next Actions と実装進捗の同期が遅れる可能性がある。
- 改善ポイント:
  - 着手/完了時に `STATUS.md` を必ず更新する運用をチェック手順に追加する。

### P5. 設計判断ログの空欄解消（`refactor`）
- 課題:
  - `docs/architecture/module-map.md` の auto-generated TODO が未記入。
- 改善ポイント:
  - 背景/判断/影響範囲を埋め、将来の変更判断に使える状態にする。

## 運用ルール
1. ブランチ名は分類接頭辞を付ける（例: `refactor/...`, `feat-core/...`, `gui-cleanup/...`）
2. Issue/PRには分類ラベルを1つ以上付与する
3. 機能追加は必要に応じて複数ラベルを併用してよい（例: `feat-audio` + `gui-feature`）
4. フェーズ分けは必要時に別ドキュメント化し、本ファイルは優先度一覧の母体として維持する
