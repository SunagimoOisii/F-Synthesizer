# PRODUCT_POLICY

## 方針概要

- 最優先価値: `音の気持ちよさ`
- 想定ユーザー: `自分専用` + `完全初心者`
- ブランドトーン: `遊び心重視`
- UI優先順位: `即時フィードバック最優先`
- リリース方針: `身内向けに配布しつつ、publicリポジトリで継続公開`

## MVP体験（必須）

- `FM音源などレトロゲームにあるサウンドに触れられる`

補足:
- 理論説明より「触って音が変わる体験」を優先する
- 失敗しにくく、短時間で気持ちよい結果に到達できる導線を優先する

## 非目標（当面やらない）

- 高度DAW機能
- プロ向け深いパラメータ
- プラグイン対応
- 共同編集

## 開発判断ルール

1. 追加機能は「音の気持ちよさ」に直接効くかを最優先で判定する
2. 初心者が迷う操作は減らし、即時試聴できる導線を優先する
3. UI文言は専門用語より目的語（何が起きるか）を優先する
4. 複雑化する機能は後回しにし、まず気持ちよい基本体験を磨く

## 方式間責務分離（重複禁止）

- 合成方式ごとの責務は明確に分離し、同じ機能を複数方式へ重複実装しない
- 共通化すべき機能は、方式へ追加する前に共通レイヤーへ切り出す
- 方式境界の判断は `docs/synth-methods/method-boundaries.md` を正とする
- 方式追加/拡張時は、`docs/synth-methods/foundation-contract.md` と境界ガイドを同時更新する

## 当面の成功指標（運用）

- 初回起動から初回プレビュー再生までの時間が短い
- 1セッション内の試行回数（編集→試聴の往復）が多い
- 「狙ったレトロ感の音が出せた」という主観評価が高い
