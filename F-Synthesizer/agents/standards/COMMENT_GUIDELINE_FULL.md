## 3. このプロジェクト固有の差分ルール

### 3.1 API対の使い分けは明記する

次のように誤用しやすい対になるAPIは、どちらを使うべきかを必ず記載する。

- 例: `Reset` と `SetTarget`
- 例: 「即時反映」系と「段階追従」系

記載最低条件:
- どの状況で使うか
- 誤用時に何が壊れるか（音切れ、状態不整合など）

### 3.2 スレッド前提は省略しない

audio処理とUI処理の境界を跨ぐ可能性がある箇所では、呼び出し主体を明示する。

- 記載例: 「前提: audio thread からのみ呼ぶ」

### 3.3 境界値の丸めは範囲まで書く

`clamp` や丸め処理に触れるコメントは、対象範囲を必ず併記する。

- 良い例: `0.0..1.0 に丸める`
- 悪い例: `クランプする`

### 3.4 エラー処理の方針を明記する

失敗を握りつぶす、既定値へ代替する、処理継続する、のいずれかを明示する。

- 返却値で通知するか
- ログへ残すか
- 完全に無視するか

### 3.5 用語の平易化（日本語文）

誤読を生みやすい抽象語だけを禁止対象として扱う。禁止語を使う場合は具体条件を同じブロックに書く。

対象語:
- `境界`（対象不明）
- `正規化`（何をどう揃えるか不明）
- `クランプ`（範囲不明）

## 4. 迷ったときの決定手順

1. `COMMENT_GUIDELINE.md` の必須ルールに該当するか確認する。
2. 該当しなければコメントを追加しない。
3. 追加する場合は 2-4 行で「目的/前提/副作用」から2項目を書く。
4. それでも判断できないときだけ本書 3章を適用する。

## 5. 運用メモ

- 本書は差分管理専用とし、一般論の追加は禁止。
- 規約追加時は「外部規約で代替不能な理由」を `docs/DECISIONS.md` に残す。
